# Unterrichtscockpit

Local-first Progressive Web App für Unterrichtsplanung und -durchführung auf iPads. Produktiv: https://bschoepkedev.github.io/unterrichtscockpit/

Version 0.8.0 ergänzt lokalen PDF-Export für kompakte und vollständige Unterrichtspläne sowie konkrete Durchführungen. PDF-Dateien enthalten je nach Auswahl Planmetadaten, Lernziele, Unterrichtspunkte, Anpassungen, Status, Soll-/Ist-Zeiten und Notizen. Download funktioniert lokal; Drucken öffnet das PDF im Browser, Teilen wird nur bei Web-Share-Unterstützung angeboten. PDF-Erzeugung und optionale Freigabe verwenden keine Exportdienste. Version 0.7.0 ergänzte schriftliche Notizen pro Unterrichtsplan und unabhängiger Durchführung sowie optionale Browser-Spracherkennung. Das iPad-Tastaturdiktat funktioniert im normalen Textfeld. Browser-Spracherkennung kann je nach Browser einen Online-Dienst verwenden; sie wird erst nach bewusster Aktivierung gestartet. Version 0.6.2 behebt einen Safari-/iPadOS-Fehler beim Lesen des PDF-Textstreams. Die App zeigt Version und kurze Build-ID zur Standprüfung. Version 0.6.1 ergänzte Vollseiten-OCR für PDFs mit Text in eingebetteten Bildern und eine downloadbare Importvorlage. Version 0.6.0 führte den lokalen PDF- und Textimport mit PDF.js, deutscher Tesseract-OCR, regelbasierter Strukturierung, bearbeitbarer Vorschau und lokalem Originalanhang ein. Dateien und Ergebnisse verlassen das Gerät nicht. OCR und automatische Feldzuordnung können Fehler enthalten; jede Vorschau muss vor dem Speichern geprüft werden.

## Lokale Entwicklung

Node.js 22 verwenden. `npm ci`, `npm run dev`, `npm run typecheck`, `npm run test`, `npm run build`, `npm run preview` und `npm run test:e2e`. Für Browserprüfungen zunächst `npx playwright install chromium webkit` ausführen. GitHub Actions führt Abhängigkeitsprüfung, Typprüfung, Unit- und Browserprüfungen sowie den Pages-Deploy aus.

## Import

Unter **Import** können PDF-, TXT-, Markdown- und CSV-Dateien oder eingefügter Text verarbeitet werden. PDF-Dateien bis 30 MB und 120 Seiten werden seitenweise untersucht. Seiten mit weniger als 80 lesbaren Zeichen werden lokal mit dem deutschen Tesseract-Sprachmodell per OCR gelesen. Optional kann OCR für alle Seiten erzwungen werden, etwa wenn eine Seite auswählbaren PDF-Text und zusätzlich Text in einem Bild enthält. Dateien, OCR-Daten und Ergebnisse werden nicht an einen Server übertragen. PDF-Text, OCR und Zuordnungen bleiben editierbar; Vorschau, Teilen, Zusammenführen und Reihenfolge können vor der Bestätigung angepasst werden. Erst das Speichern im Planeditor schreibt den Plan und den Originalanhang gemeinsam in IndexedDB. Der Originalanhang ist anschließend über die Plan-Karte in der Bibliothek erreichbar.

Die regelbasierte Erkennung ist für beliebige Dokumentlayouts nicht garantiert. Unsichere Zeiten, OCR- und Mehrspalteninhalte erhalten Prüfhinweise. Tabellen, Stichpunkte, nummerierte Zeilen und gemischte Inhalte werden unterstützt, müssen aber durch die Lehrkraft geprüft werden. DOCX-Dateien werden derzeit nicht importiert; Inhalte daraus können in den Editor kopiert oder als PDF/TXT exportiert werden.

## iPad, Datenschutz und Datenhaltung

In Safari über **Teilen → Zum Home-Bildschirm** installieren. Pläne, Durchführungen, Notizen und Anhänge werden ausschließlich lokal in IndexedDB gespeichert, nicht auf GitHub. Das Tastaturdiktat ist eine Funktion von iPadOS. Für die optionale Browser-Spracherkennung gelten die Datenverarbeitungsbedingungen des jeweiligen Browsers beziehungsweise seines Spracherkennungsdienstes; eine lokale Audioverarbeitung wird nicht zugesichert. Es wird kein eigener Speech-Dienst eingebunden. Browserdaten können verloren gehen. Bis zur Implementierung vollständiger Sicherungen in Stufe 9 keine unersetzlichen Daten speichern. Der Import-Build bündelt die benötigten PDF- und OCR-Ressourcen im Service-Worker-Precache. Vollständige Offline- und iPad-Safari-Abnahme ist noch offen und wird nicht durch automatisierte WebKit-Tests ersetzt.
